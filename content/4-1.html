4.1

산업용 IoT 게이트웨이

OT와 IT 간 데이터 통역사 — 현장의 말을 사무실의 말로

현장 설비는 CC-Link나 Modbus로 말한다. 사무실 시스템은 인터넷의 언어로 말한다. 두 세계는 말이 통하지 않는다. 그 사이에 서서 통역하고, 모으고, 정리하고, 지켜 주는 장치가 IoT 게이트웨이다. 2.1의 계층 그림에서 정확히 가운데 자리다.

이 장을 읽고 나면

  1. OT와 IT의 차이와, 왜 둘 사이에 번역이 필요한지 설명할 수 있다.
  2. 게이트웨이의 네 가지 역할(변환·취합·보안·전처리)을 구분할 수 있다.
  3. Modbus·CC-Link와 MQTT·OPC UA의 성격 차이를 이해한다.
  4. 게이트웨이가 보안 관문 역할을 하는 이유와 기술자의 준수 사항을 안다.
  5. 게이트웨이 이상 시 설비에 어떤 영향이 있는지 판단할 수 있다.
4.1.1

OT와 IT는 다른 세계다우선하는 가치가 정반대다

OT는 멈추지 않는 것이 최우선이고, IT는 정보가 새지 않는 것이 최우선이다. 이 차이가 두 세계의 모든 설계를 갈라놓았다.

OT(Operational Technology)는 현장 설비를 움직이는 기술이다. PLC, 서보 드라이브, 센서가 여기 속한다. IT(Information Technology)는 정보를 다루는 기술이다. 서버, 데이터베이스, 클라우드가 여기 속한다.

개념 · 왜 OT는 업데이트를 잘 안 하나

사무실 PC는 매달 보안 패치를 받는다. 그러나 컨베이어를 돌리는 PLC를 패치하려면 라인을 세워야 하고, 패치 후 동작이 달라질 위험이 있다. 그래서 OT 기기는 “잘 돌아가면 건드리지 않는다”가 원칙이다. 이 원칙이 안정성을 주지만 보안 취약점을 오래 남긴다. 게이트웨이가 보안 관문 역할을 맡는 이유가 여기 있다.

4.1.2

게이트웨이의 네 가지 역할변환 · 취합 · 보안 · 전처리

게이트웨이는 통역사이자, 짐꾼이자, 문지기이자, 검수원이다. 네 가지를 한 장치가 동시에 한다.

① 프로토콜 변환 — 말을 바꾼다

현장 규격(Modbus, CC-Link, PROFINET)으로 온 데이터를 IT 규격(MQTT, OPC UA)으로 바꿔 내보낸다. 단순히 형식만 바꾸는 것이 아니라, “레지스터 40001의 값 1234”를 “3번 컨베이어의 속도 12.34 m/min”으로 의미를 붙여 주는 일까지 포함한다.

② 데이터 취합 — 묶어서 보낸다

설비 수십 대의 데이터가 제각각 올라가면 상위 시스템이 감당하지 못한다. 게이트웨이는 일정 시간 동안 모아서 패키지로 묶어 한 번에 보낸다. 네트워크 부담이 크게 줄고, 상위에서 처리하기도 쉬워진다.

③ 보안 관문 — 문지기 역할

현장 네트워크와 사무실 네트워크 사이의 유일한 통로가 되어, 허가되지 않은 접근을 막고 데이터를 암호화한다. 본문 4에서 자세히 다룬다.

④ 전처리 — 보내기 전에 정리한다

1.4에서 본 노이즈 섞인 값, 단위가 제각각인 값(mm와 m가 섞인)을 정리한다. 2.2에서 스마트센서가 내부에서 하던 일을, 일반 센서가 붙은 설비에 대해 게이트웨이가 대신 해 주는 셈이다.

현장 · 게이트웨이는 어디에 있나

대개 제어반 안이나 현장 배전반 안에 DIN 레일에 붙은 작은 상자다. PLC와 비슷하게 생겼고, 통신 포트가 여러 개 달려 있다. LAN 포트 하나는 현장 쪽, 다른 하나는 사무실 쪽으로 연결되어 있는 것이 특징이다. 이 두 포트를 서로 바꿔 꽂으면 보안 구조가 무너진다.

4.1.3

두 세계의 통신 규격무엇이 어떻게 다른가

현장 규격은 정해진 것을 정해진 때에 주고받는다. IT 규격은 필요한 사람이 필요한 것을 받아 간다.

개념 · OPC UA가 특별한 이유

다른 규격은 “값 1234”를 전달한다. OPC UA는 “3번 컨베이어의 속도, 단위는 m/min, 정상 범위는 0~30, 측정 시각은 언제”를 함께 전달한다. 받는 쪽이 값의 뜻을 몰라도 되므로, 새 시스템을 붙일 때 매번 해석 규칙을 만들 필요가 없다. 이 성질 때문에 OT와 IT의 경계에서 표준처럼 쓰인다.

4.1.4

보안 관문 역할현장 네트워크를 지키는 유일한 문

현장 설비는 보안을 염두에 두고 만들어지지 않았다. 그래서 설비를 고치는 대신 문을 하나만 두고 그 문을 지킨다.

PLC와 센서는 “네트워크에 나쁜 사람이 있을 수 있다”는 전제로 설계되지 않았다. 비밀번호가 없거나 기본값 그대로인 경우도 흔하다. 그런 기기들이 인터넷에 직접 연결되면 공장이 통째로 위험해진다.

표 4.1-2 · 게이트웨이가 수행하는 보안 기능
기능하는 일없으면
방화벽허가된 통신만 통과시킨다외부에서 PLC에 직접 접근 가능
단방향 제어데이터는 위로만, 명령은 막는다외부에서 설비 조작 시도 가능
암호화전송 중 데이터를 읽을 수 없게 한다생산 정보·설비 구성이 노출
기기 인증등록된 기기만 데이터를 보낼 수 있다위조 데이터 주입 가능
접근 기록누가 언제 무엇을 했는지 남긴다사고 발생 시 원인 추적 불가
주의 · 기술자가 반드시 지킬 것
  • 현장 네트워크에 개인 기기를 연결하지 않는다 — 노트북, 휴대폰 테더링, USB 저장장치
  • 임시 공유기·스위치를 임의로 설치하지 않는다 — “잠깐만”이 영구가 된다
  • 게이트웨이의 LAN 포트를 바꿔 꽂지 않는다 — 현장 쪽과 사무 쪽이 뒤바뀐다
  • 기기 비밀번호를 공유하거나 메모로 붙여 두지 않는다
  • 원격 접속 요청은 반드시 담당자를 통한다 — 벤더 지원도 예외가 아니다
4.1.5

실무 보강게이트웨이 이상을 판단하고 대응한다

게이트웨이가 죽으면 데이터는 멈추지만 설비는 대개 돈다. 이 구분을 아는 것이 야간 호출 여부를 가른다.

아래 다섯 항목은 목차에 명시되어 있지는 않지만 물류설비 운영에서 실제로 필요해 보강한 내용이다.

1. 게이트웨이 이상의 영향 판단

3.3 실무 보강 4의 “설비 정지 vs 데이터 정지”를 여기에 적용한다.

표 4.1-3 · 이상 위치별 영향
이상 위치설비데이터긴급도
게이트웨이 자체 정지정상 동작상위 전송 중단보통
게이트웨이–상위 회선 두절정상 동작상위 전송 중단보통
게이트웨이–현장 회선 두절정상 동작수집 중단보통
게이트웨이가 제어에도 관여해당 구간 정지중단긴급
제어반 전원 이상전 구간 정지중단긴급
현장 · 우리 설비는 어느 쪽인가를 미리 확인해 둔다

대부분의 게이트웨이는 데이터 수집 전용이라 죽어도 설비는 돈다. 그러나 일부 구성에서는 게이트웨이가 상위 지시(주문 정보 등)를 받아 전달하기도 한다. 이 경우 게이트웨이가 죽으면 라인이 선다. “우리 라인의 게이트웨이는 어느 쪽인가”를 미리 확인하면 장애 시 판단이 즉시 선다.

2. 데이터가 안 올라올 때의 확인 순서

현장 → 게이트웨이 → 상위 순으로 좁힌다.

  1. 설비는 정상인가 — 라인이 돌고 있으면 제어 계통은 문제없다
  2. 게이트웨이 전원·상태 LED — 꺼져 있으면 전원 계통
  3. 현장 쪽 통신 LED — 이상이면 PLC와의 연결 문제
  4. 상위 쪽 통신 LED — 이상이면 사무 네트워크·회선 문제
  5. 일부만 안 올라오는가, 전부인가 — 일부면 그 설비의 수집 설정, 전부면 게이트웨이
  6. 언제부터인가 — 최근 네트워크 공사·설비 추가 이력 확인
개념 · 데이터는 나중에 채울 수 있다

게이트웨이는 대개 버퍼를 갖고 있어, 상위 연결이 끊긴 동안의 데이터를 내부에 저장했다가 복구되면 한꺼번에 올린다. 그래서 몇 시간 끊겼다고 데이터가 영영 사라지는 것은 아니다. 다만 버퍼 용량을 넘기면 오래된 것부터 지워진다. 장시간 두절은 그래서 문제가 된다.

3. 설비를 추가·교체했는데 데이터가 안 올라온다면

가장 흔한 게이트웨이 관련 문의.

게이트웨이는 어떤 설비의 어떤 값을 읽을지가 설정으로 정해져 있다. 설비를 새로 달거나 형번이 다른 것으로 교체하면 그 설정을 갱신해야 한다. 2.3의 자동 파라미터 설정은 센서–마스터 사이의 이야기이고, 게이트웨이의 수집 설정은 별개다.

  • 새 설비 추가 → 게이트웨이에 수집 대상 등록 필요 (담당자)
  • 같은 형번 교체 → 대개 그대로 동작
  • 다른 형번 교체 → 데이터 주소·형식이 달라 재설정 필요
  • 설비 위치 이동 → 통신 주소가 바뀌면 재설정 필요
현장 · 전달할 정보

“무엇을, 언제, 무엇으로 바꿨는지”를 정확히 전달하면 담당자가 설정만 고치면 된다. 특히 기존 형번과 새 형번을 둘 다 알려 주는 것이 핵심이다.

4. 보안 사고를 부르는 현장 관행

악의가 없어도 사고는 난다.

표 4.1-4 · 흔한 위험 행동과 대안
흔한 행동위험대안
현장 PC에 개인 USB 연결악성코드가 현장망으로지정된 매체만 사용, 담당자 경유
휴대폰 테더링으로 임시 인터넷경계 우회 — 게이트웨이 무력화절대 금지. 필요 시 담당자에게 요청
벤더에게 원격 접속 허용통제되지 않은 외부 접근담당자 입회·기록 하에만
기본 비밀번호 유지누구나 설정 변경 가능담당자에게 변경 요청

주의 · 물류 현장이 표적이 되는 이유

물류 현장은 멈추면 즉시 생산이 밀린다. 설비가 인터넷과 연결된 경우가 많으며, 24시간 운영되어 감시가 느슨한 시간대가 있다. 공격자에게는 매력적인 조건이다. “우리 구역은 규모가 작으니 괜찮다”는 판단은 근거가 없다.

5. 현장 점검 체크리스트

게이트웨이 관련 점검 항목.

상태

  • 게이트웨이 전원·상태 LED가 정상인가
  • 현장 쪽·상위 쪽 통신 LED가 모두 정상인가
  • 제어반 내부 온도가 과도하지 않은가 (게이트웨이는 발열에 약하다)
  • 데이터가 상위 화면에 정상적으로 갱신되고 있는가

보안

  • 현장 네트워크에 허가되지 않은 기기가 연결되어 있지 않은가
  • 임시 공유기·스위치·연장 케이블이 방치되어 있지 않은가
  • 제어반이 잠겨 있고 접근이 통제되는가
  • 비밀번호가 적힌 메모가 붙어 있지 않은가

변경 시

  • 설비를 추가·교체한 뒤 데이터가 정상 수집되는지 확인했는가
  • 형번이 바뀐 경우 담당자에게 기존·신규 형번을 전달했는가
개념 · 이 장이 남기는 것

OT와 IT는 우선하는 가치가 달라 직접 연결할 수 없고(본문 1), 게이트웨이가 변환·취합·보안·전처리 네 가지를 맡는다(본문 2). 현장 규격은 묻고 답하는 방식, IT 규격은 발행·구독 방식이다(본문 3). 게이트웨이는 현장망을 지키는 유일한 문이며, 그 경계를 우회하면 의미가 사라진다(본문 4).
다음 장 4.2에서는 그 문을 지나가는 데이터를 어떻게 줄이고 무엇을 남길지의 정책을 다룬다.

현장 설비를 감시·제어하는 기술 영역. PLC·드라이브·센서가 속하며 가용성을 최우선으로 한다.
IT (Information Technology)
정보를 저장·처리·전달하는 기술 영역. 서버·데이터베이스·클라우드가 속하며 기밀성을 최우선으로 한다.
IoT 게이트웨이
OT와 IT 사이에서 프로토콜 변환·데이터 취합·보안·전처리를 수행하는 장치.
Modbus
가장 널리 쓰이는 산업용 통신 규격. 단순하고 개방적이어서 구형 설비에도 폭넓게 적용된다.
CC-Link IE
미쓰비시전기 계열의 산업용 이더넷 규격. 고속·결정론적 통신을 제공한다.
MQTT
가볍고 느슨한 발행/구독 방식의 메시지 프로토콜. 대역폭이 좁거나 지연이 큰 회선에 강하다. ISO/IEC 20922로 표준화되어 있다.
OPC UA
값에 의미(단위·범위·시각)를 붙여 전달하는 산업용 통신 표준. 보안 기능이 내장되어 있으며 IEC 62541로 규정된다.
폴링 (Polling)
제어기가 주기적으로 각 기기에 값을 묻고 답을 받는 방식. 순서와 타이밍이 보장된다.
발행/구독 (Publish/Subscribe)
보내는 쪽이 변화를 알리면 필요한 쪽이 받아 가는 방식. 여러 시스템이 같은 데이터를 동시에 쓸 수 있다.
버퍼 (Buffer)
상위 연결이 끊긴 동안 데이터를 임시 저장하는 공간. 복구되면 밀린 데이터를 전송한다.
