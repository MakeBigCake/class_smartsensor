## 무엇을 다루는가

설비가 멈췄을 때 현장 기술자에게 필요한 것은 센서를 분해할 공구가 아니라, **「이 센서는 무엇을 보고 있었고, 무엇을 못 보게 되었는가」를 판단할 언어**다. 이 책은 고장의 원인을 끝까지 규명하는 방법이 아니라, 원인이 생긴 계통을 빨리 좁혀 설비 중단 시간을 줄이는 방법을 다룬다.

설비별로 나누지 않고 **데이터가 흘러가는 순서**로 나눴다.

웹 페이지 26개는 원고에서 자동으로 생성된다. **손으로 고치지 않는다.** 다만 GitHub Pages가 이 파일들을 직접 서비스하므로 저장소에는 올라가 있어야 한다.

```
content/                ← 고치는 곳은 여기뿐이다
  cover.html              표지 본문 (차례 · 통계 · 부 도해)
  preface.html            머리말
  1-1.html … 4-3.html     본문 15장

assets/style.css        모든 스타일 (표지 포함)

build.py                content/ → 웹 페이지 21개. 목차·번호·부 도입 면 자동 생성
make_back.py            찾아보기 5종 생성 (용어 · 그림 · 표 · 약어 · 참고문헌)
bundle.py               전체를 단일 HTML 파일로 묶기
refdata.py              발행처 표기 · 자료 종류 · 약어 목록
```

## 수정하는 순서

`content/` 안의 파일만 고치고 아래를 차례로 실행한다. 목차·그림 번호·표 번호·색인·내부 링크·앞뒤 이동은 전부 자동으로 다시 만들어진다.

```bash
python3 build.py        # 웹 페이지 21개 (표지 · 머리말 · 부 도입 4 · 본문 15)
python3 make_back.py    # 찾아보기 5종
python3 bundle.py       # 단일 파일

git add .
git commit -m "무엇을 고쳤는지 한 줄"
git push
```

표준 라이브러리만 쓴다. 설치할 것이 없다.

`make_back.py`는 실행할 때마다 수집 건수를 출력하고, 하나라도 0이면 멈춘다. 본문 마크업과 추출 규칙이 어긋나면 색인이 조용히 비는 사고를 막기 위한 장치다.

```
수집: 용어 132 · 참고 230 · 그림 66 · 표 62
```

## 읽는 순서

앞뒤 이동은 26면이 한 줄로 이어진다.

```
표지 → 머리말 → 1부 도입 → 1.1 … 1.4
             → 2부 도입 → 2.1 … 2.4
             → 3부 도입 → 3.1 … 3.4
             → 4부 도입 → 4.1 … 4.3
             → 용어 색인 → 그림 색인 → 표 색인 → 약어 목록 → 참고문헌
```

## 만들 때 지킨 것

- 색은 6가지만 쓴다. 강조색(골드)은 **주의**에만 쓴다
- 계층은 색과 크기가 일치한다 — 책 제목·부는 네이비 면, 장은 틴트 띠, 절은 네이비 제목
- 강조 상자는 개념 · 현장 · 주의 세 종류만 쓴다
- 표의 수치에는 출처를 붙인다. 없으면 「저자 판단」이라고 적는다
- 링크는 실제로 열어 내용을 확인한 것만 쓴다. 응답 코드로 판단하지 않는다
- 도해의 글자는 선에 가리지 않는다 (66개 전수 검사)
